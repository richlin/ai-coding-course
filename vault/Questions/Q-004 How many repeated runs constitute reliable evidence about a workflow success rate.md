# Q-004 — How many repeated runs constitute reliable evidence about a workflow's success rate?

The non-determinism lesson says one passing run proves "can succeed" not "reliably succeeds," and warns against interpreting short streaks as trends. But it doesn't specify a threshold.

**The open question:** What sample size is needed to make a meaningful claim about a workflow's success rate for a given task? Does this depend on the tail risk (how bad the worst runs are) or on the base rate? Is there practical guidance from ML reliability literature that transfers here?
