# Rerouting When Evidence Changes the Destination — AI Coding Course

## Summary
Rerouting is deliberate adaptation — changing the plan when new evidence (code, tests, users, production data, dependencies, security constraints) invalidates the current approach or goal — as distinct from silent scope drift. Gives the structure of a "reroute note" and requires explicit human approval before continuing.

## Key takeaways
- Stop at the first decision an invalidated assumption affects; state what evidence changed and which assumption it invalidated, rather than patching a symptom to preserve a disproven plan.
- A reroute note separates newly discovered facts from the recommended direction, and names cost, discarded work, and migration impact.
- The agent surfaces the contradiction and options; the human owns approval of a product or risk tradeoff — the agent does not silently reroute on its own authority.
- Preserve completed work only when it still supports the revised goal; don't discard valid tests or components merely because the surrounding architecture changed, and don't keep executing old tickets once the controlling spec has changed.
