# Intent, Assumptions, Constraints, and Non-Goals — AI Coding Course

## Summary
A four-part framework for bounding a task: intent (the outcome), assumptions (beliefs treated as true until checked), constraints (limits on acceptable solutions), non-goals (what the task deliberately won't solve). Directly closes the gap an agent would otherwise fill with its own guesses, differently from the requester.

## Key takeaways
- Describe the outcome before prescribing implementation details; name the user and the decision the outcome supports, not just the feature.
- Surface uncertain assumptions explicitly so they can be checked early, rather than letting them hide inside a requirement.
- Write non-goals for the specific nearby work that is tempting but unnecessary — "out of scope" without naming what's excluded doesn't constrain anything.
- Don't hide an unresolved product decision inside an assumption; don't confuse an implementation preference with an actual outcome or constraint.
- Verification test: ask a peer or fresh agent to name two plausible interpretations still allowed by the boundary — revise only where those interpretations would cause incorrect work.
