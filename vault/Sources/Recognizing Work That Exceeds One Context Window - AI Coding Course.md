# Recognizing Work That Exceeds One Context Window — AI Coding Course

## Summary
A task is too large when one session cannot hold its goals, evidence, active decisions, and verification state clearly — a claim about cognitive and coordination load, not file count. Signals include many independent subsystems, unclear dependencies, repeated compaction, and changes that cannot be reviewed together as one coherent diff; the practical move is decomposing before the session starts degrading rather than after.

## Key takeaways
- Task size is about cognitive and coordination load, not the number of files touched — a one-file parser change with many lines may still fit one context.
- Split work when it contains independently valuable outcomes, and isolate unknown or high-risk work as separate research tasks before committing to full implementation.
- Estimate decision and integration boundaries, not tokens alone, and keep one named owner for the full outcome even after splitting.
- Do not wait until context is already degraded before deciding a task is too large — decompose before that point.
- Do not split tightly coupled edits into artificial tickets, and do not call a task small just because the prompt describing it is short.
