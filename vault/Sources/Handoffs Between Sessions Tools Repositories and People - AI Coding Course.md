# Handoffs Between Sessions, Tools, Repositories, and People — AI Coding Course

## Summary
Extends the handoff document beyond the session-boundary case already in the vault to any transfer point: harness, repository, owner, or branch of work. A handoff is written for a reader with repository access but no prior conversation, and should lead with current state and next action rather than a chronological summary.

## Key takeaways
- Write for a reader with repository access but no prior conversation — the same standard whether the receiver is a fresh session, a different tool, or a different person.
- Separate verified facts from assumptions, decisions, and recommendations — don't blend them into one narrative.
- State exactly which checks ran and their scope ("tests pass" without commands and scope is not useful).
- Link durable artifacts (spec, ticket, diff, decision record) instead of copying their content.
- Don't hide blockers or risk to make progress look cleaner; update the handoff if work continues after writing it.
