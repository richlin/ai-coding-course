# Fresh Sessions and Clearing Context — AI Coding Course

## Summary
A fresh session starts with no active conversation history; clearing is useful when the task changes or existing reasoning has become unreliable, because old assumptions can anchor an agent even after the direction changed. The new session should start from durable artifacts, not from memory of the old one.

## Key takeaways
- Save work, decisions, failures, and next steps before clearing — don't clear first and try to reconstruct state afterward from memory.
- Start the new session from durable artifacts and a concrete first action, not by pasting the old transcript.
- Use a fresh session for a distinct task, for independent review (so it isn't anchored by prior implementation discussion), or to recover from deep confusion — not merely to avoid resolving an unclear requirement.
- "Fresh" does not mean free of repository instructions or durable decisions — those still load.
