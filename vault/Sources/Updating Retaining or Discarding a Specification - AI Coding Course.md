# Updating, Retaining, or Discarding a Specification — AI Coding Course

## Summary
Treats a spec as a living decision artifact while work is active: update it when accepted requirements/constraints/decisions change, retain it when it explains durable behavior or tradeoffs, archive or remove it when it's temporary and superseded. A stale spec can mislead more than having none.

## Key takeaways
- Record *why* a meaningful requirement changed — durable rationale prevents re-litigating settled decisions later.
- Mark superseded documents clearly and link to the replacement; don't keep multiple active specs for the same behavior.
- Don't update code while leaving acceptance criteria knowingly false, and don't treat a merged spec as automatically correct forever — review specs when code behavior or policy changes.
- After delivery: retain user-visible behavior and rationale, archive temporary investigation notes — not everything gets kept, and not everything gets thrown away.
